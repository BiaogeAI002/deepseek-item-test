# deepseek-item-test v0.1 PRD

> 状态：待架构设计确认 | 负责人：产品经理 | 日期：2026-11-21
> 定位：流程演练项目，规模刻意压小，规格以「可被 unittest 直接验证」为标准。

## 1. 项目目标

给个人开发者一个**零依赖**的本地待办清单命令行工具 `item`。装好 Python 3.11 即可用，数据存本地 JSON 文件，不联网、不装包。

成功判定（v0.1 交付即满足）：

1. 5 条命令手工跑通：`add` / `list` / `done` / `rm` + `--help`。
2. `python -m unittest` 全绿，覆盖每条命令与全部分支错误。
3. 7d-code-reviewer 审查无 🔴 严重问题。
4. README 有可直接复制的用法示例。

## 2. 目标用户与核心场景

- **目标用户**：习惯终端的开发者；不想为记一条待办去开网页或装 App。
- **核心场景**：想到一件事 → `item add "买牛奶" --due 2026-11-25` → 需要时 `item list` 扫一眼 → 做完 `item done 1`。
- **非目标用户**：需要多人协作、提醒推送、图形界面的用户。

## 3. 范围边界

**做什么（v0.1）**：单机单人待办的新增、查看、完成、删除、JSON 持久化。

**明确不做（且不在 v0.1 讨论）**：

| 不做 | 原因 |
|---|---|
| 优先级、标签、分类、备注 | 超出演练范围 |
| 修改（edit）、清空已完成 | 可由 rm + add 替代 |
| 提醒 / 定时推送 | 需要常驻进程 |
| 搜索、过滤、排序选项 | list 输出量小 |
| 多用户、并发写、云端同步 | 单机单人场景 |
| 第三方依赖、打包成 exe | 硬性零依赖 |
| 图形 / 交互式 TUI | 命令行即可 |

## 4. 功能清单与验收标准

优先级：P0 = v0.1 必须，P1 = 可选加分，P2 = 后续版本。

### 4.1 P0 — 命令

**F1 `item add <内容> [--due YYYY-MM-DD]`**

验收标准：

- 成功时 **仅在 stdout 输出新 id**（纯数字，无其他文字），退出码 0，退出后数据已落盘。
- id 为整数，从 1 开始自增，**删除后不复用**（取历史最大值 +1）。
- 内容去除首尾空白后写入；`--due` 省略时截止日期为空。
- 空内容 / 全空白内容 → stderr 报错，退出码非 0，**文件不变**。
- `--due` 不是 `YYYY-MM-DD` 或不是真实日期（如 `2026-02-30`）→ stderr 报错，退出码非 0，文件不变。
- 内容含空格、中文、emoji 时：原样存取，list 中可完整显示。

**F2 `item list`**

验收标准：

- 一次输出全部条目，按 id 升序，每行一条：
  - 未完成：`<id> [ ] <内容>`
  - 已完成：`<id> [x] <内容>`
  - 有截止日期时行尾追加 ` due:YYYY-MM-DD`
- 空清单输出一行 `暂无待办`，退出码 0（不报错）。
- 只读操作：不修改数据文件。

**F3 `item done <id>`**

验收标准：

- 将指定 id 标记为已完成并落盘，输出确认信息，退出码 0；再次 `list` 显示 `[x]`。
- 对已完成的 id 重复执行 → 视为幂等成功，退出码 0，不报错、不重复写入。
- id 不存在 / 非整数 / 缺参数 → stderr 报错，退出码非 0，文件不变。

**F4 `item rm <id>`**

验收标准：

- 删除指定条目并落盘，输出确认信息，退出码 0；该 id 之后不再出现在 list 中。
- id 不存在 / 非整数 / 缺参数 → stderr 报错，退出码非 0，文件不变。
- 删除不会导致其他条目的 id 变化。

**F5 持久化**

验收标准：

- 数据文件路径：默认 `~/.item.json`；环境变量 `ITEM_FILE` 有值时以其为准（含相对路径与含空格路径）。
- 文件不存在时按空清单处理，首次 `add` 自动创建（父目录存在的前提下）。
- 文件为 UTF-8 JSON，人工可读（含缩进），内容含中文时不转义为 `\uXXXX` 亦可接受（实现自选，但 round-trip 必须无损）。
- 写入为**原子操作**（先写临时文件再替换），任何时刻不留下半截文件。

**F6 错误处理（统一约定）**

验收标准：

- 损坏 JSON（非法 JSON 或结构不符）→ stderr 明确报错并带文件路径，退出码非 0，**绝不覆盖原文件**、绝不静默当空清单。
- 未知子命令 / 缺必填参数 / 多余参数 → 打印用法到 stderr，退出码非 0。
- 所有错误信息写 stderr，错误信息以 `错误:` 开头；正常输出写 stdout。
- 无子命令 → 打印用法到 stderr，退出码非 0；`-h` / `--help` → 用法写 stdout，退出码 0。

**F7 文档**

- README.md：安装前提（Python 3.11，零依赖）、5 条命令用法示例、`ITEM_FILE` 说明、退出码约定、如何跑测试。
- docs/PRD.md 即本文件。

## 5. 非功能要求

- **零依赖**：仅 Python 3.11 标准库，`import` 不得出现在要求 `pip install` 的包上。
- **启动快**：`list` 100 条数据在普通笔记本上 < 0.3s（体感即可）。
- **可用性**：所有命令在 Windows（PowerShell/CMD）与 Linux/macOS 下行为一致；路径用 `pathlib` 处理，不写死分隔符。
- **编码**：文件读写显式 `encoding="utf-8"`，避免 Windows 下 GBK 乱码。
- **健壮性**：任何异常路径都不产生 traceback 直接抛给用户（顶层捕获并转为 `错误:` 信息），除非 `--debug`（v0.1 不做）。
- **可维护性**：单文件实现（后续可拆模块），函数职责单一，便于写测试。

## 6. 建议的 JSON 结构（供架构师确认，非强制）

```json
{
  "version": 1,
  "next_id": 3,
  "items": [
    {"id": 1, "text": "买牛奶", "done": false, "due": "2026-11-25"},
    {"id": 2, "text": "写周报", "done": true, "due": null}
  ]
}
```

约定：`items` 缺失或非数组视为结构损坏；单条记录缺 `id`/`text` 视为结构损坏；`done` 缺省按 `false`、`due` 缺省按 `null` 容错读取。
